# 📡 Инструкция: система рассылок + мониторинг переписок на SaleBot

> Краткое описание архитектуры и ключевых нюансов. Конкретные имена файлов, пути, названия сервисов и эндпоинтов — придумывай сам под свой проект. Этот документ объясняет **что должно быть**, а не **как назвать**.

---

## 🎯 Из чего состоит система

Четыре независимых компонента, работающих в связке:

1. **Бот-интерфейс для команд** — отдельный Telegram-бот, через которого вы и ваша команда управляете рассылками в закрытом групповом чате.
2. **Бот рассылок** — другой Telegram-бот, от имени которого реально уходят сообщения подписчикам.
3. **Мониторинг переписок** — сервис, который принимает webhook-и от SaleBot (все входящие/исходящие сообщения личного TG-аккаунта через Telegram Business), складывает их в базу и шлёт AI-отчёты.
4. **Веб-дашборд** — закрытый интерфейс для просмотра клиентов, переписок и статистики.

Компоненты 1 и 2 — это обычно один процесс (скрипт с aiogram). Компоненты 3 и 4 — второй процесс (веб-сервер aiohttp + HTML-страница + SQLite).

## 🧩 Подводные камни SaleBot (обязательно знать ДО кода)

### 1. Два клиента на одного человека
SaleBot создаёт **две отдельные записи** на одного и того же пользователя:
- `client_type = 16` — Telegram Business (ваш личный аккаунт)
- `client_type = 1` — его же диалог с ботом рассылки

У них **разные `platform_id`, но одинаковый `tg_username`**.
**Связка возможна ТОЛЬКО по `tg_username`**, не по platform_id.

### 2. Нельзя узнать «в каких списках состоит клиент»
SaleBot API не отдаёт списки конкретного клиента. Приходится идти с другой стороны: перебирать все списки по ID и смотреть, есть ли в них этот клиент. На большой базе это десятки минут из-за rate limit — делай такую синхронизацию по расписанию (раз в неделю достаточно).

### 3. Формат `attachments` ломается между endpoint-ами
Webhook присылает вложения **строкой** вида `"['url1','url2']"` — нужно парсить через `ast.literal_eval` или `json.loads` с заменой кавычек.
`get_history` отдаёт нормальный JSON-массив объектов `[{"attachment_url": "...", "attachment_type": "..."}]`.
Нормализуй оба формата к единому виду `["url1", "url2"]`.

### 4. Webhook Telegram для бота рассылок принадлежит SaleBot
Когда подключаешь бота к SaleBot — **Telegram webhook URL настраивает сам SaleBot**. Никогда не перезаписывайте его своим `setWebhook` — сломаете всю систему рассылок.

### 5. API считается в лимит сообщений
Любой вызов SaleBot API (кроме `save_variables`) съедает из квоты тарифа. Используй кэш клиентов и не дёргай API без нужды.

### 6. Fallback при таймаутах API
Если SaleBot не ответил — **НЕ обнуляй кэш** клиентов. Оставь старый, webhook-и пропускай как есть. Иначе при временном сбое API у тебя рухнет весь мониторинг.

## 🔐 Переменные окружения (концепт)

Понадобятся примерно такие ключи (имена придумай свои):

- Два Telegram-бот-токена: для команд и для рассылок
- API-ключ SaleBot
- API-ключ Anthropic (Claude) для AI-анализа
- Белый список username-ов, которым разрешено давать команды боту
- ID рабочего группового чата
- ID тестовых пользователей (для превью рассылок)
- Токен для защиты дашборда
- Секрет для проверки подлинности SaleBot-webhook
- Реквизиты VPS (если деплоишь на свой сервер)

Храни всё в `.env`, никогда не коммить в git. В `.env.example` оставь только названия без значений.

## 💾 Что хранить в базе

Минимум четыре концептуальные таблицы (назови как хочешь, хранилище на выбор — SQLite простейший вариант):

1. **Сообщения** — одна строка = одно сообщение, с направлением (in/out), текстом, вложениями, датой.
2. **Диалоги** — по одной записи на клиента: username, имя, аватар, время последнего сообщения, флаг «неотвечено более часа».
3. **Профили клиентов** — связка бизнес-клиента и бот-клиента по username + данные из переменных SaleBot (email, телефон, город, роль, списки, подписка на бота).
4. **AI-кэш** — сгенерированная сводка по клиенту + количество сообщений на момент генерации. Если счётчик не изменился — не перегенерируй.

## 🤖 AI-анализ переписок

Два уровня работы с Claude:

- **Дешёвая массовая** модель (например, Haiku) — короткая сводка по каждому клиенту: о чём диалог, горячий ли лид, рекомендация следующего шага.
- **Дорогая аналитическая** модель (например, Sonnet) — ежедневный общий дайджест в рабочий чат: кого не забыть, где тревожные сигналы, какие приоритеты на завтра.

Перед вызовом AI — **всегда проверяй кэш**. Если по клиенту не появилось новых сообщений с момента последней генерации, возьми старую сводку.

Предусмотрите возможность **через команду бота добавлять пользовательские инструкции** для AI (на что обращать внимание, что игнорировать). Храните их отдельно и подмешивайте в system prompt каждого запроса.

## 🌐 Webhook SaleBot → твой сервер

В админке SaleBot прописывается Webhook URL — адрес твоего сервиса мониторинга. SaleBot шлёт туда POST с JSON по каждому сообщению.

**Обязательные защиты:**
- Секрет в query string — иначе любой может слать фейковые сообщения.
- Webhook должен принимать запрос и **сразу отвечать 200**, а обработку складывать в очередь. SaleBot агрессивно ретраит на медленных ответах.

## 📱 Дашборд

Закрытая веб-страница для вас и вашей команды:
- Список клиентов с фильтром по дате
- Переписка с выбранным клиентом (включая медиа)
- Профиль клиента в хедере (email, телефон, роль, город, списки, подписка)
- Блок статистики (сообщений за день, горячих лидов, неотвеченных)

**Защита — один-единственный токен в query string**. Для внутреннего инструмента этого достаточно, но это слабая защита: не давайте ссылку никому кроме команды, меняйте токен при ротации людей.

На мобилке — табы (клиенты / чат / статистика). На десктопе — две колонки.

## 🖥️ Деплой

Любой VPS с Python 3.10+, nginx и SSL. Два процесса под systemd (или supervisor, или Docker — на вкус):
- Процесс бота
- Процесс мониторинга + веб-сервера

nginx проксирует внешний HTTPS → localhost-порт веб-сервера.

**Важно для бота рассылок**: перед рестартом проверяйте наличие lock-файла, который создаётся на время активной рассылки. Если рассылка идёт — отмените рестарт, иначе оборвёте её посреди потока сообщений подписчикам.

## 🚨 Правила «не ломать»

1. **НЕ перезаписывайте Telegram webhook** бота рассылок — он у SaleBot.
2. **НЕ обнуляйте кэш клиентов** при таймауте SaleBot API — используйте fallback.
3. **НЕ связывайте `platform_id`** между type=1 и type=16 — связка только по username.
4. **НЕ запускайте полную синхронизацию параллельно** — используйте asyncio-lock.
5. **НЕ кладите секреты в код** — только `.env` + EnvironmentFile на VPS.
6. **НЕ давайте webhook-у работать без проверки секрета** в query string.
7. **НЕ отдавайте дашборд без проверки токена**.
8. **Веб-сервер должен стартовать до готовности SaleBot API** — иначе при лагах API сервис не поднимется. Загружайте кэш клиентов фоновой задачей.

## ⚙️ Технические рекомендации

- **Одна глобальная HTTP-сессия** на весь процесс, TCP connection pool ~20 соединений.
- **Retry** на сетевые ошибки: 2 попытки с короткой паузой.
- **Ссылки на юзеров** делайте через `https://t.me/<username>`, `tg://user?id=...` работают не во всех клиентах.
- **Rate limit для SaleBot**: ~1 запрос/сек безопасно.
- **Ежедневный отчёт и синхронизация профилей** по cron/asyncio-таске — в вечернее время по локальному часовому поясу, когда рабочий день завершён.
